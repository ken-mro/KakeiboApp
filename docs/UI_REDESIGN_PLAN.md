# UI刷新計画

家計簿アプリの見た目と操作を、日常的に安心して使える完成度に引き上げるための計画です。
デザインは承認済みです（下の「デザインの方向性」を参照）。段階1〜4と6をバージョン2.0で実装し、段階5は対象外とします。

## 目的

- 開いた瞬間に「今月あといくら使えるか」と「このペースで大丈夫か」がわかる画面にする
- 表を直接編集しなくても、迷わず入力・修正できるようにする
- ライト・ダークの両テーマ、文字サイズの拡大、色覚の違いに対応する

成功の目安は次のとおりです。

| 指標 | 現在 | 目標 |
|---|---|---|
| 残りのお金を確認するまでの操作 | ホームを下にスクロールする | 起動直後に表示されている |
| 生活費を1件登録する操作 | タブ移動 → 5項目入力 → 登録 | ホームから追加ボタン → 金額と種類 → 登録 |
| 行を削除する方法 | 金額に0を入力（説明がないと分からない） | スワイプして削除、取り消し可能 |
| ダークテーマの崩れ | 月ボタンが明るいまま | 全画面でテーマに追従 |

## 現状の課題

スクリーンショットとXAMLを確認して分かった課題です。

1. **配色がテンプレートのまま**
   - `Resources/Styles/Colors.xaml` はMAUIの初期値（紫 `#512BD4`、マゼンタのタブ）です。家計簿らしさや意味を持っていません。
   - セクションの色（`#DFF5E3` など）は `MainPage.xaml` に直接書かれており、テーマとして管理されていません。
2. **ダークテーマへの追従漏れ**
   - 月選択ボタンは `BackgroundColor="LightGray"`、`TextColor="Black"` の固定値です。
   - 表の選択色も `Lavender`／`DarkSlateBlue` の直書きです。
3. **一番大事な数字が下にある**
   - 「残りのお金」は6つあるセクションの5番目です。毎回スクロールしないと見えません。
4. **情報の密度が均一**
   - 6つのセクションが同じ大きさ・同じ形の折りたたみで並び、重要度の差が見えません。
5. **編集と削除が分かりにくい**
   - 表のセルを直接編集し、金額に0を入れると削除される仕様は、説明を読まないと気付けません。
   - 誤って削除しても取り消せません。
6. **入力画面の配置**
   - 追加画面は画面上端に張り付き、片手では「登録」ボタンに指が届きにくい位置です。
   - 登録後も開いたままで、閉じ方（外側をタップ）が示されていません。
7. **細部**
   - タブとセクションのアイコンの線の太さがそろっていません。
   - 「内訳」「種類ごとの内訳」などの見出しが中央寄せと左寄せで混在しています。
   - データがない月は空の表が表示されるだけで、次に何をすればよいかが分かりません。

### コンセプト：ころんと、やさしい家計簿

家計簿は、続けることがいちばん大切です。数字に追い立てられる画面ではなく、毎日ひらきたくなる、まるくてやわらかい画面にします。

- 角はまるく、色はパステルにして、ぶたの貯金箱のマスコットがそっと寄り添う
- 文言はやわらかくする（「生活費をつける」「いくら使った？」「けす」「もとに戻す」など）
- 赤みのピンク（`Deficit`）は、予算オーバーと削除にだけ使う。装飾には使わない
- 種類ごとに色とアイコンを決め、文字を読まなくても種類がわかるようにする

### 一番印象に残す要素：残りのお金と今月のペース

ホームの最上部に「残りのお金」と「今月のペース」を1枚のカード（`Hero`）で表示します。
ペースは、月の経過日数の割合と、使えるお金の消化割合を2本のバーで並べて見せます。使った割合が日数の割合より先に進んでいれば、使いすぎのサインです。
カードの下には、ぶたからのひとことを吹き出しで表示します（例：「ちょっと早めのペースです」）。

```
┌──────────────────────────────────┐
│ 残りのお金                   (ぶた) │
│ ¥90,000                          │
│ 1日あたり ¥5,294    あと17日      │
│ ┌──────────────────────────────┐ │
│ │ 日数 ━━━━━━━━━━──────────  15/31日 │ │
│ │ 支出 ━━━━━━━━━━━━━━━━────    70% │ │ ← 日数より先なら Deficit
│ └──────────────────────────────┘ │
│ （ちょっと早めのペースです。…）    │
└──────────────────────────────────┘
```

## デザイントークン

`Colors.xaml` と `Styles.xaml` を作り直し、画面からは意味のある名前（トークン）だけを参照します。直接の色指定はなくします。

| `Ink` | 本文・数字 | `#4A3B52` | `#F8EEF6` |
| `InkMuted` | 補足・ラベル | `#75657E` | `#C9B9D1` |
| `Paper` | 背景 | `#FFF5F7` | `#231B2A` |

| `Accent` | 押せる要素 | `#7C5CC4` | `#C7B3FF` |
| `OnAccent` | `Accent` の上の文字 | `#FFFFFF` | `#2A2033` |
| `AccentSoft` | 選択中・チップ | `#EFE8FF` | `#3E3354` |
| `AccentInk` | 選択中の文字・リンク | `#5F43A8` | `#DCCFFF` |
| `Deficit` | 使いすぎ・削除（面・線） | `#E0566F` | `#FF91A4` |

### 種類ごとの色

アイコンの背景・アイコン・バーの3色を、種類ごとに決めます。ライト・ダークで共通です。

| 種類 | アイコンの背景 | アイコン | バー |
|---|---|---|---|
| 食費 | `#FFE3EA` | `#B23A62` | `#F28AA8` |
| 日用品・雑貨 | `#DDF3EA` | `#2E7A5E` | `#6CC3A0` |
| 娯楽 | `#FFF0C2` | `#8A6A00` | `#EDBE45` |
| 車 | `#DDEBFF` | `#2F62A8` | `#78A8EC` |
| 医療 | `#ECE4FF` | `#6247B0` | `#A98DE6` |
| その他 | `#F0EAE3` | `#7A6450` | `#BFA88F` |

予算を超えた種類は、バーを `Deficit`、金額を `DeficitInk` にし、「オーバー」のバッジを付けます。色だけに頼らず、文字でもわかるようにします。

### 文字

- 書体は **Zen Maru Gothic** の1書体にします。
  - まるみのあるゴシック体で、コンセプトのやわらかさに合います。
  - Google Fontsが無料で配布しており、アプリに同梱できます（SIL Open Font License）。
  - 現在のOpen Sansは日本語を含まず、日本語は端末の標準書体で表示されているため、画面ごとに見え方がそろっていません。
  - Regular・Medium・Boldの3つの太さを同梱し、既定の書体にします。
- 文字サイズの段階は次の5段階に限定します。

| 名前 | サイズ | 太さ | 用途 |
|---|---|---|---|
| `Display` | 42 | Bold | 残りのお金 |
| `Title` | 22 | Bold | 画面タイトル |
| `Body` | 16 | Regular | 本文、一覧の行 |
| `Label` | 14 | Medium | 見出しラベル、補足 |
| `Caption` | 12 | Regular | 日付、注記 |

- 見出しやラベルは左寄せにそろえます。数字は右寄せにします。

### 余白・角・影

- 余白は4の倍数（4・8・12・16・24・32）を基本にします。
- 角の丸みは役割で分けます。カードは28、ボタンは高さの半分（丸い形）、チップは22です。
- 影は、押せる主役（「生活費をつける」ボタンとタブバー）だけに、ラベンダー色で薄く付けます。カード同士は背景との色の差で分けます。

### マスコット

- ぶたの貯金箱（SVG）を、ホームの残りのお金のカードと、データがない月の画面に表示します。
- データがない月は、眠っているぶたにします。

## 画面構成

### ホーム

折りたたみ6つを並べる構成をやめ、「概要 → 詳細」の2段構成にします。

```
        ‹   2026年10月   ›
┌─────────────────────────────────────┐
│ [残りのお金と今月のペース（上の図）]  │  ← Hero
└─────────────────────────────────────┘
┌─────────────────────────────────────┐
│ 今月使えるお金            ¥300,000   │
│ (収) 収入             ¥400,000    › │
│ (貯) 貯金             −¥50,000    › │
│ (家) 固定費           −¥50,000    › │
└─────────────────────────────────────┘
┌─────────────────────────────────────┐
│ 生活費      ¥210,000 / 予算 ¥200,000 │
│ (食) 食費 オーバー ¥120,000 / ¥100,000│  ← 予算超過は Deficit
│      ██████████████████████████     │
│ (日) 日用品・雑貨   ¥30,000 / ¥40,000 │
│      ███████████████░░░░░░░░░░      │
│   …                                 │
└─────────────────────────────────────┘
┌ (特) 特別出費                ¥50,000 › ┐
│      別枠です。残りのお金には入りません │
└──────────────────────────────────────┘
┌ (貯) 貯金の内訳・切り崩し            › ┐
                       [＋ 生活費をつける]
 ( ホーム | 一覧 | 特別出費 | 設定 )         ← 浮いたタブバー
```

- 月は、タイトルの左右にある「‹」「›」で切り替えます。タイトルをタップすると年月を選べます。
- 「今月使えるお金」は、収入 − 貯金 − 固定費を計算式の順で上から並べます。各行をタップすると一覧画面に移ります。
- 生活費は種類ごとに予算の消化率を横棒で表示します。種類をタップすると、その月の予算を入力するシートが開きます。
- 特別出費は「別枠です。残りのお金には入りません」と明記し、残りのお金に含まれないことを画面上で示します。

### 一覧・編集

- 収入・貯金・固定費・生活費・特別出費の一覧は、同じ形のリスト画面に統一します（`CollectionView`）。
- 生活費と特別出費は日付ごとにまとめ、見出しに「10月16日（金）」のように表示します。
- 一覧の上に、件数と合計を表示します。
- 行をタップすると編集シートが開きます。表のセルを直接編集する方式は廃止します。
- 行を左にスワイプすると「けす」ボタンが出ます。けすと画面下に「『ランチ』をけしました」と「もとに戻す」ボタンを数秒表示します。
- 「金額に0を入れると削除」の仕様は廃止します。

### 入力シート

- 追加と編集は、画面下から出るシートに統一します。親指で届く位置に「登録」ボタンを置きます。
- 生活費の入力は、「いくら使った？」（金額）→「なにに使った？」（種類）の順にし、内容・メモ・日付は「メモや日付も書く（なくてもOK）」を開いたときだけ表示します。
- 種類は一覧から選ぶのではなく、アイコン付きのボタンを3列に並べて1タップで選べるようにします。
- 続けて登録するかどうかを利用者が選べるよう、「つづけて登録」と「登録」を分けます。
- 編集のときは「けす」と「保存」のボタンにします。

### 空の状態

データがない月は、空の表ではなく次の行動を示します。

- 眠っているぶたと「11月はまだまっしろです」という見出し、「給料などの収入を入れると、今月使えるお金と1日あたりの金額がわかります」という説明、「収入を入れる」ボタンを表示します。
- 前月に固定費がある場合は、「10月の固定費が5件あります」と「11月にコピーする」ボタンを表示します。

## 文言

- 操作の名前は最初から最後まで同じにします。「登録」ボタンを押したら、通知は「登録しました」です。
- エラーは何が起きたかと、どうすればよいかを書きます。
  - 現在は「登録に失敗しました。もう一度試してください」のように、原因が分かりません。
  - 変更後は「金額を入力してください。1円以上の金額を登録できます」のように、原因ごとに分けます。
- 「切り崩し」には、初回のみ短い説明を添えます（「貯金から今月の生活に回したお金です」）。

## アクセシビリティ

- 文字と背景のコントラスト比はWCAG AA（本文4.5:1以上）を満たします。トークン決定時に全組み合わせを確認します。
- 予算オーバーは色だけで区別せず、「オーバー」のバッジを付けます。残りのお金がマイナスのときは「−」記号を付けます。
- すべてのボタンとアイコンに `SemanticProperties.Description` を設定し、読み上げに対応します。
- タップ領域は44×44以上にします。
- 端末の文字サイズ設定を200%にしても、金額が切れたり重なったりしないことを確認します。

## リスクと対策

| リスク | 対策 |
|---|---|
| Syncfusionの表から `CollectionView` に変えると、グループ表示や集計を自前で作る必要がある | 集計は `BudgetCalculator` に寄せてテストで守る。グループ表示は `CollectionView` の `IsGrouped` を使う |
| 操作方法が変わり、今の使い方に慣れた利用者が戸惑う | 初回起動時とアップデート後の初回起動時に、アプリ内の「使い方」を表示する。「設定 › 使い方」からいつでも見られる |
| 書体の同梱でアプリのサイズが増える | 使う太さをRegular・Medium・Boldの3つに絞る |
| 既存データとの互換性 | データベースの構造は変えない。画面と計算の変更に限定する |
