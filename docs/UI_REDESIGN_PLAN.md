# UI刷新計画

家計簿アプリの見た目と操作を、日常的に安心して使える完成度に引き上げるための計画です。
この文書は計画のみで、コードはまだ変更していません。

## 目的

- 開いた瞬間に「今月あといくら使えるか」と「このペースで大丈夫か」が分かる画面にする
- 表を直接編集しなくても、迷わず入力・修正できるようにする
- ライト・ダークの両テーマ、文字サイズの拡大、色覚の違いに対応する

成功の目安は次のとおりです。

| 指標 | 現在 | 目標 |
|---|---|---|
| 残りのお金を確認するまでの操作 | ホームを下にスクロールする | 起動直後に表示されている |
| 生活費を1件登録する操作 | タブ移動 → 5項目入力 → 登録 | ホームから追加ボタン → 金額と種類 → 登録 |
| 行を削除する方法 | 金額に0を入力（説明がないと分からない） | スワイプして削除、取り消し可能 |
| ダークテーマの崩れ | 月ボタンが明るいまま | 全画面でテーマに追従 |

## 現状の課題

スクリーンショットとXAMLを確認して分かった課題です。

1. **配色がテンプレートのまま**
   - `Resources/Styles/Colors.xaml` はMAUIの初期値（紫 `#512BD4`、マゼンタのタブ）です。家計簿らしさや意味を持っていません。
   - セクションの色（`#DFF5E3` など）は `MainPage.xaml` に直接書かれており、テーマとして管理されていません。
2. **ダークテーマへの追従漏れ**
   - 月選択ボタンは `BackgroundColor="LightGray"`、`TextColor="Black"` の固定値です。
   - 表の選択色も `Lavender`／`DarkSlateBlue` の直書きです。
3. **一番大事な数字が下にある**
   - 「残りのお金」は6つあるセクションの5番目です。毎回スクロールしないと見えません。
4. **情報の密度が均一**
   - 6つのセクションが同じ大きさ・同じ形の折りたたみで並び、重要度の差が見えません。
5. **編集と削除が分かりにくい**
   - 表のセルを直接編集し、金額に0を入れると削除される仕様は、説明を読まないと気付けません。
   - 誤って削除しても取り消せません。
6. **入力画面の配置**
   - 追加画面は画面上端に張り付き、片手では「登録」ボタンに指が届きにくい位置です。
   - 登録後も開いたままで、閉じ方（外側をタップ）が示されていません。
7. **細部**
   - タブとセクションのアイコンの線の太さがそろっていません。
   - 「内訳」「種類ごとの内訳」などの見出しが中央寄せと左寄せで混在しています。
   - データがない月は空の表が表示されるだけで、次に何をすればよいかが分かりません。

## デザインの方向性

### コンセプト：藍の帳面と朱の赤字

家計簿は、紙の帳面に黒いインクで書き、足りない分を赤いインクで書く文化から生まれました。「黒字」「赤字」という言葉もそこから来ています。
このアプリでは、その語彙をそのまま画面の約束事にします。

- 文字と数字は藍色のインクで書く
- 赤（朱）は「赤字」のときだけ使う。装飾には使わない
- 背景は罫線の入った帳面のように静かにし、数字を主役にする

一般的な家計簿アプリにある、カテゴリごとに鮮やかな色が並ぶ見た目は採用しません。色の意味を「黒字と赤字」の区別だけに絞ることで、ひと目で状況が分かる画面にします。

### 一番印象に残す要素：今月のペース

ホームの最上部に「残りのお金」と「今月のペース」を1枚で表示します。
ペースは、月の経過日数の割合と、使えるお金の消化割合を、2本の細い線で重ねて見せます。使った割合が日数の割合より先に進んでいれば、使いすぎのサインです。
このアプリで大胆にするのはこの1か所だけです。ほかの要素は静かにそろえます。

```
┌──────────────────────────────────┐
│ 2026年10月                    ‹ › │
│                                  │
│ 残りのお金                        │
│ ¥90,000                          │  ← 黒字は藍、赤字は朱
│ 1日あたり ¥5,294    あと17日      │
│                                  │
│ 日数 ━━━━━━━━━━━━━━━──────────── 15/31 │
│ 支出 ━━━━━━━━━━━━━━━━━━━━━━━━──── 70%  │  ← 日数より先なら朱
└──────────────────────────────────┘
```

## デザイントークン

`Colors.xaml` と `Styles.xaml` を作り直し、画面からは意味のある名前（トークン）だけを参照します。直接の色指定はなくします。

### 色

| トークン | 用途 | ライト | ダーク |
|---|---|---|---|
| `Ink` | 本文・数字（黒字） | `#1D2B44` 藍墨 | `#E6EAF2` |
| `InkMuted` | 補足・ラベル | `#5A6478` | `#9AA4B5` |
| `Paper` | 背景 | `#F7F8FA` | `#141B26` |
| `Surface` | カード・シート | `#FFFFFF` | `#1C2532` |
| `Rule` | 罫線・区切り | `#E1E5EC` | `#2C3646` |
| `Accent` | 操作できる要素 | `#2F5D9E` 藍 | `#8FB0E3` |
| `Deficit` | 赤字・使いすぎ・削除 | `#C23B2E` 朱 | `#FF8A7A` |
| `Surplus` | 黒字の強調（必要な場合のみ） | `#2E6B4F` | `#7CC4A0` |

セクションの区別には色ではなく、アイコンと見出しを使います。どうしても色で区別する場合は、`Rule` と同程度の淡い色を左端の細い線にだけ使います。

### 文字

- 書体は **BIZ UDPゴシック** の1書体にします。
  - モリサワのユニバーサルデザイン書体で、数字の0とO、1とlなどが見分けやすく、お金の表示に向いています。
  - Google Fontsが無料で配布しており、アプリに同梱できます（SIL Open Font License）。
  - 現在のOpen Sansは日本語を含まず、日本語は端末の標準書体で表示されているため、画面ごとに見え方が揃っていません。
- 金額は等幅数字で表示し、桁を縦にそろえます。
- 文字サイズの段階は次の5段階に限定します。

| 名前 | サイズ | 太さ | 用途 |
|---|---|---|---|
| `Display` | 40 | Bold | 残りのお金 |
| `Title` | 22 | Bold | 画面タイトル、セクションの合計 |
| `Body` | 16 | Regular | 本文、表の行 |
| `Label` | 14 | Regular | 見出しラベル、補足 |
| `Caption` | 12 | Regular | 日付、注記 |

- 見出しやラベルは左寄せにそろえます。数字は右寄せにします。

### 余白・角・影

- 余白は4の倍数（4・8・12・16・24・32）だけを使います。
- 角の丸みは役割で分けます。カードは12、入力欄とボタンは8、タグは4です。
- 影は使いません。面の区切りは `Rule` の線と `Surface`／`Paper` の明るさの差で表します。

## 画面構成

### ホーム

折りたたみ6つを並べる構成をやめ、「概要 → 詳細」の2段構成にします。

```
┌ 2026年10月 ‹ › ─────────────────────┐
│ [今月のペース（上の図）]             │
├─────────────────────────────────────┤
│ 今月使えるお金            ¥300,000   │
│   収入   ¥400,000                 › │
│   貯金   −¥50,000                 › │
│   固定費 −¥50,000                 › │
├─────────────────────────────────────┤
│ 生活費      ¥210,000 / 予算 ¥200,000 │
│   食費     ██████████  ¥120,000   › │  ← 予算超過は朱
│   日用品   ██████░░░░  ¥30,000    › │
│   …                                 │
├─────────────────────────────────────┤
│ 特別出費（別枠）           ¥50,000 › │
│ 貯金の内訳・切り崩し              › │
└─────────────────────────────────────┘
                         [＋ 生活費を記録]
```

- 「今月使えるお金」は、収入 − 貯金 − 固定費を計算式の順で上から並べます。各行をタップすると一覧画面に移ります。
- 生活費は種類ごとに予算の消化率を横棒で表示します。予算を超えた種類は棒と金額を `Deficit` にします。
- 特別出費は「別枠」と明記し、残りのお金に含まれないことを画面上で示します。

### 一覧・編集

- 収入・貯金・固定費・生活費・特別出費の一覧は、同じ形のリスト画面に統一します（`CollectionView`）。
- 行をタップすると編集シートが開きます。表のセルを直接編集する方式は廃止します。
- 行を左にスワイプすると削除し、画面下に「削除しました」と「元に戻す」ボタンを数秒表示します。
- 「金額に0を入れると削除」の仕様は廃止します。

### 入力シート

- 追加と編集は、画面下から出るシートに統一します。親指で届く位置に「登録」ボタンを置きます。
- 生活費の入力は、金額 → 種類 →（任意）内容・メモ・日付の順にし、最小2操作で登録できるようにします。
- 種類は一覧から選ぶのではなく、ボタンを並べて1タップで選べるようにします。
- 続けて登録するかどうかを利用者が選べるよう、「登録して続ける」と「登録」を分けます。

### 空の状態

データがない月は、空の表ではなく次の行動を示します。

- 例：「10月の収入はまだありません。給料などを追加すると、今月使えるお金が計算されます」という説明と「収入を追加」ボタンを表示します。
- 固定費が空で前月にデータがある場合は、「9月の固定費をコピー」を表示します。

## 文言

- 操作の名前は最初から最後まで同じにします。「登録」ボタンを押したら、通知は「登録しました」です。
- エラーは何が起きたかと、どうすればよいかを書きます。
  - 現在は「登録に失敗しました。もう一度試してください」のように、原因が分かりません。
  - 変更後は「金額を入力してください。1円以上の金額を登録できます」のように、原因ごとに分けます。
- 「切り崩し」には、初回のみ短い説明を添えます（「貯金から今月の生活に回したお金です」）。

## アクセシビリティ

- 文字と背景のコントラスト比はWCAG AA（本文4.5:1以上）を満たします。トークン決定時に全組み合わせを確認します。
- 黒字・赤字は色だけで区別せず、赤字の金額には「−」記号と「赤字」の表示を付けます。
- すべてのボタンとアイコンに `SemanticProperties.Description` を設定し、読み上げに対応します。
- タップ領域は44×44以上にします。
- 端末の文字サイズ設定を200%にしても、金額が切れたり重なったりしないことを確認します。

## 実装の段階

一度にすべてを変えず、段階ごとにリリースできる単位で進めます。各段階で、変更前と変更後のスクリーンショットをライト・ダークの両方で撮って比較します。

### 段階1：トークンとスタイル

- 内容
  - `Colors.xaml`／`Styles.xaml` をトークンで作り直す
  - BIZ UDPゴシックを同梱して既定の書体にする
  - `MainPage.xaml` などに直書きされた色をトークンに置き換える
- 完了条件
  - XAML内に `#` で始まる色の直書きと `LightGray` などの色名が残っていない
  - ダークテーマで全画面の文字と背景が追従している

### 段階2：ホームの概要

- 内容
  - 「今月のペース」と「今月使えるお金」の概要を実装する
  - ペースの計算（経過日数の割合と消化率）を `BudgetCalculator` に追加し、テストを書く
- 完了条件
  - 起動直後のスクロールなしの範囲に、残りのお金とペースが表示される
  - 計算式を `docs/FORMULAS.md` に追記している

### 段階3：一覧と編集シート

- 内容
  - 共通のリスト画面と下から出る編集シートを作る
  - スワイプ削除と取り消しを実装する
  - 表の直接編集と「0で削除」を廃止する
- 完了条件
  - すべての種類のデータで、追加・編集・削除・取り消しが動く
  - `docs/HOW_TO.md` を新しい操作に合わせて更新している

### 段階4：入力の短縮

- 内容
  - ホームの「生活費を記録」ボタンと、金額 → 種類の2操作で登録できるシートを作る
- 完了条件
  - 生活費1件の登録が、ホームから3タップ以内で完了する

### 段階5：グラフ

- 内容
  - 種類ごとの予算消化の横棒、月ごとの残りのお金の推移
  - グラフには `Syncfusion.Maui.Charts` を使う（既存のライセンスで利用可能）
- 完了条件
  - グラフの値が一覧の合計と一致することをテストで確認している

### 段階6：仕上げとアクセシビリティ確認

- 内容
  - 空の状態、エラー文言、読み上げ、文字サイズ200%の確認
- 完了条件
  - 上の「アクセシビリティ」の項目をすべて満たしている

## リスクと対策

| リスク | 対策 |
|---|---|
| Syncfusionの表から `CollectionView` に変えると、グループ表示や集計を自前で作る必要がある | 集計は `BudgetCalculator` に寄せてテストで守る。グループ表示は `CollectionView` の `IsGrouped` を使う |
| 操作方法が変わり、今の使い方に慣れた利用者が戸惑う | 段階3のリリース時に、初回だけ新しい削除方法を案内する |
| 書体の同梱でアプリのサイズが増える | 使う太さをRegularとBoldの2つに絞る |
| 既存データとの互換性 | データベースの構造は変えない。画面と計算の変更に限定する |
